#### Description

`facebook/bart-large-mnli` is the BART-large checkpoint (Lewis et al., arXiv:1910.13461) after fine-tuning on the MultiNLI natural-language-inference dataset, published by Facebook AI on the Hugging Face Hub and pinned here to revision `d7645e127eaf1aefc7862fd59a17a5aa8558b8ce`. BART is a denoising sequence-to-sequence Transformer: a 12-layer bidirectional encoder and a 12-layer autoregressive decoder with `d_model` 1024, 16 attention heads, a 50 265-entry byte-level BPE vocabulary and 1024 positions (snapshot `config.json`), 407 344 133 float32 parameters in the pinned `model.safetensors` (counted from the SafeTensors header). The MNLI fine-tune replaced generation with a three-way classification head (`contradiction`, `neutral`, `entailment`) read from the decoder's final end-of-sequence state. Zero-shot classification follows Yin et al. (arXiv:1909.00161), as the upstream README describes: the text to classify is the NLI premise, each caller-supplied label is inserted into the hypothesis template `This example is {label}.` (`HYPOTHESIS_TEMPLATE`), and the entailment and contradiction logits of each pair become a per-label score. No adaptation happens at inference — no training, fine-tuning or in-context conditioning; the pinned checkpoint is used as published. What this repository adds is packaging and a bounded adaptation contract: the `BARTZeroShotClassificationPipeline` class in `src/bart_zero_shot_classification_pipeline/pipeline.py`, digest verification of the local snapshot (`verify_snapshot`, `stage_missing_files`), input validation against named ceilings, the score conversion in NumPy, a fixed output contract, corpus-level classification metrics with a majority baseline (`metrics.py`: accuracy, macro-F1, per-label precision/recall/F1), a digest-pinned real labelled corpus (`samples.py`: Banking77, ten intents with readable label phrases, validated and split without leakage), supervised fine-tuning of the last *k* decoder blocks and the classification head (`adapt`, default 2 of 12) on entailment/contradiction pairs built from the labelled texts with validation-accuracy epoch selection, and a safetensors adapter (`save_artifact` / `from_artifact`) that carries only the trained tensors and is bound to the base weight digest.

#### Intended Use and Limitations

###### Primary Intended Uses

Zero-shot text classification: input one English string and a list of 1–`MAX_LABELS = 32` unique label names chosen by the caller at call time; output one score per label, sorted descending, plus the `top_label`. With `multi_label=False` (default) the entailment logits are soft-maxed across the labels so the scores sum to one and exactly one label is best; with `multi_label=True` each label is scored independently by a softmax over its own contradiction and entailment logits, for texts that may belong to several classes at once. The upstream README's own example — `one day I will see the world` against `travel`, `cooking`, `dancing` — is the shape of task intended: topic tagging, intent routing, content triage, or bootstrapping labels for a corpus before a supervised model exists, wherever the label names are ordinary English phrases the hypothesis template can carry. In a larger system the pipeline is a zero-configuration baseline and a labelling aid whose output a human or a downstream model consumes; it is not a decision engine. The second intended use is bounded adaptation to a fixed label set: given 8–20,000 `{id, text, label}` records whose labels are short readable phrases, `adapt` turns every record into one entailment pair (its gold phrase) and one contradiction pair (a seeded wrong phrase), fine-tunes the last two decoder blocks and the NLI head (34,646,019 parameters, about 9 % of the model) for a few epochs, selects the epoch by validation accuracy, and `save_artifact` exports the trained tensors as a 139 MB safetensors adapter that `from_artifact` applies on top of the digest-verified base — the recorded run lifts held-out Banking77 accuracy over ten intents from 82.50 to 97.00 and macro-F1 from 81.39 to 96.99 in about 3 minutes of CPU training. The adapted model is still a zero-shot scorer: it accepts any label set and template, but it has been pulled towards the phrases and template it was trained on.

###### Primary Intended Users

Machine-learning engineers, NLP researchers and application developers integrating an off-the-shelf zero-shot classifier into research prototypes or in-house tooling, and adapting it to a fixed label set for which they hold a small labelled corpus. The pipeline assumes its users understand that the score is derived from an NLI entailment logit and is a ranking signal rather than a calibrated probability of class membership, that the quality of the result depends on how well the label wording fits the hypothesis template (`This example is sports.` reads naturally; a label such as `Q3 revenue variance` does not), that the checkpoint is English-only and 407 M parameters (~1.6 GB float32, roughly 6 s to load and 0.1–0.6 s per call on the CPU used here), that accuracy and macro-F1 measure exact top-label agreement with gold labels on one split and are not calibration measures, and that a fine-tuned adapter is only as good as the split discipline and the label phrasing behind it. It is not designed for hobbyist "point and trust" use.

###### Out-of-scope use cases

1. **Capability boundary:** not text generation or summarisation — the classification head replaces the language-model head (the `bart-cnn-summarization-pipeline` sibling covers summarisation); not natural-language inference on arbitrary premise/hypothesis pairs, because `classify` always builds the hypothesis from the template and the raw three-way NLI logits are exposed only as `entailment_logit`/`contradiction_logit` per label; not sentence embeddings or token-level tagging. Not a trained classification head over a fixed vocabulary: `adapt` keeps the NLI formulation — the adapted model still scores any label set through the template — and is not a general training framework: it fine-tunes only whole decoder blocks (1–12 of them, the last *k*) plus the classification head, with AdamW, a fixed learning rate, no scheduler, no mixed precision, no gradient accumulation, one contradiction pair per record and no early stopping beyond epoch selection; the encoder, the embeddings and the vocabulary are never modified, so it cannot teach the model a new language.
2. **Input boundary:** `str` premise only (`TypeError` otherwise); empty or whitespace-only text rejected; more than `MAX_TEXT_CHARS = 8000` characters rejected before tokenisation and any premise+hypothesis pair over `MAX_TEXT_TOKENS = 1024` BPE tokens rejected after it — inputs are never silently truncated; label lists outside 1–32 entries, labels over `MAX_LABEL_CHARS = 100` characters, empty or duplicate labels, and a `hypothesis_template` without exactly one `{}` are rejected. Non-English text, code, and labels that are not English noun phrases degrade without any warning from the pipeline. Datasets for `validate_dataset`, `evaluate` and `adapt` are lists of `{id, text, label}` records: fewer than `MIN_RECORDS = 8` or more than `MAX_RECORDS = 20000` records, a duplicate or malformed `id` (pattern `^[A-Za-z0-9_.:-]{1,64}$`), an empty text or one over `MAX_TEXT_CHARS`, an empty label or one over `MAX_LABEL_CHARS`, more than `MAX_LABELS` distinct labels, a label outside an explicitly supplied label set, or a record that is not a mapping is rejected with `ValueError`; `label_names` requires at least 2 distinct labels; `evaluate` accepts 1–`MAX_EVAL_RECORDS = 2000` records and applies the inference ceilings to every (text, hypothesis) pair; `adapt` requires at least `MIN_RECORDS` training records and refuses `epochs` outside 1..20, `batch_size` outside 1..64, `lr` outside (0, 1e-3], `trainable_decoder_layers` outside 1..12 or a template without exactly one `{}`. Training pairs are truncated to `MAX_TRAIN_PAIR_TOKENS = 256` tokens (the only truncation in the repository, and it applies to training only). `load_artifact` refuses an adapter whose `format`, `base_model` id, revision or `weight_sha256` differ from the constants, whose tensor names are not `model.decoder.layers.*` or `classification_head.*`, or whose file digest differs from its manifest.
3. **Decision boundary:** not for autonomous or high-impact decisions — routing complaints, screening people, moderating content, triaging medical or legal text — without a human reviewing the output and a locally measured error rate on the deployment's own labels; not for inferring attributes of individuals from text. An accuracy gain on the operator's validation split is not a release decision: it is a single seeded split of one corpus with no dispersion estimate, the scores remain uncalibrated after adaptation, and an adapter tuned to ten phrases has changed the model's zero-shot behaviour on every other label set in ways nothing here measures.

#### Factors

###### Groups

The pipeline is human-centric in the sense that its inputs are natural-language text about, and often written by, people, and the labels a caller supplies can name social groups, attributes or intents. The upstream README states only that the checkpoint is `bart-large` "after being trained on the MultiNLI (MNLI) dataset" and carries no bias or group-level statement of its own; MultiNLI is crowd-written hypotheses over premises from ten written and spoken genres, and neither the upstream card nor this repository reports any group-level performance breakdown for it or for the BART pre-training corpus. This repository ran no fairness evaluation. The obligation therefore transfers to the operator: before any deployment that touches people, run paired probes that differ only in a group term (in the premise, in the labels, or both) and compare the ranked scores, evaluate top-label accuracy stratified by the groups relevant to the application on the operator's own labelled data, and treat a material gap as a blocker.

###### Instrumentation

The training data was captured by no physical sensor: it is text. The upstream README discloses the fine-tuning set by name only — the MultiNLI dataset — and the base model's pre-training data is disclosed in the BART paper (the same corpus as RoBERTa: books, news, web text and stories). The instrument characteristics that reach the model are therefore the text-collection and crowd-annotation procedures behind those corpora, none of which the pinned README describes. At inference the only instrument is the byte-level BPE tokenizer shipped in the snapshot (`vocab.json`, `merges.txt`, `tokenizer.json`), which encodes each premise+hypothesis pair as one sequence; unusual Unicode, OCR errors, code and URLs fragment into many sub-word pieces, and the pipeline reports the longest pair's token count (`n_tokens`) but does not detect encoding drift, language change or OCR noise.

###### Environment

Operating environment: Python 3.12 with `torch==2.14.0`, `torchvision==0.29.0`, `torchaudio==2.11.0`, `transformers==4.57.6`, `tokenizers==0.22.2`, `numpy==2.5.3` (exact pins in `pyproject.toml`), float32. This is a 407 M-parameter model whose `model.safetensors` is 1 629 437 147 bytes, so it needs roughly 1.7 GB of free RAM for the weights alone. `from_pretrained(device=None)` picks `cuda:0` when available, else CPU; this repository's smoke ran on CPU only (Windows venv, `CUDA_VISIBLE_DEVICES=-1`, `device="cpu"`): loading and digest-verifying the 1.63 GB snapshot took 7.84 s, one three-label `classify` call 0.334 s, a second call with `multi_label=True` 0.091 s. Adaptation on the same machine, from the committed notebook's recorded run: reading the two pinned Banking77 files (1.1 MB) from the cache and drawing the balanced 400 / 100 / 200 sample took under a second; a ten-label `classify` call took about 0.3 s, so scoring the frozen zero-shot model on the 200-message test split took 60.8 s (accuracy 82.50, macro-F1 81.39; majority baseline 10.0 / 1.82; the weakest phrases were `ATM support` and `card arrival`); two epochs of AdamW over 800 entailment/contradiction pairs at batch 16 with the last two decoder blocks and the head trainable (34,646,019 of 407,344,131 parameters, `lr=2e-5`, weight decay 0.01, gradient clipping 1.0, seed 0) took 193 s including the per-epoch validation scoring (validation accuracy 84.00 frozen → 96.00 → 98.00; epoch 2 selected); re-scoring the test split took 48.8 s (accuracy 97.00, macro-F1 96.99); the adapter is 138,590,612 bytes over 56 tensors, and the reloaded pipeline reproduced 8/8 top labels. The CUDA path is untested in this repository. Data environment: inputs are assumed to be modern English prose of the kinds MultiNLI covers (fiction, letters, government reports, telephone speech transcripts, and similar written and spoken genres) and labels are assumed to be short English phrases that read naturally in `This example is {label}.`; behaviour on other languages, domain jargon, very long documents near the 1024-token ceiling, or label sets whose members overlap in meaning is not measured here and is expected to degrade.

#### Metrics

###### Performance Measures

Two performance measures over a labelled dataset, implemented in `src/bart_zero_shot_classification_pipeline/metrics.py` with no external scorer: **accuracy**, the fraction of texts whose `top_label` equals the gold label by exact string match, and **macro-F1**, the unweighted mean over the gold label vocabulary of the per-label F1 (precision and recall of predicting that label; a label never predicted contributes 0), both in percent, with the per-label precision, recall, F1 and support reported beside them. Accuracy reads directly off the argmax rule the pipeline applies and needs no class prior; macro-F1 is reported with it because a zero-shot scorer can be good on average and blind to one phrase — the recorded run's frozen model scored 33 F1 on `ATM support` against 100 on `the exchange rate` — and because it stays informative when a label set is imbalanced. `classification_metrics(predicted, gold)` computes both; `pipe.evaluate(records, labels, hypothesis_template=...)` classifies a validated dataset over an explicit label set and returns them with the verdict `measured` (≥ `MIN_SCORED_RECORDS = 50` records) or `measured-small-sample`, the elapsed time and the model identity; `majority_baseline(records)` predicts the most frequent gold label everywhere — exactly one over the number of labels on a balanced split. Accuracy selects the epoch in `adapt`. What a reader loses by reading these alone is any view of ranking quality below the top label and of the `multi_label` scores, which remain uncalibrated and are not evaluated. The batch `evaluation_report(results, gold_labels)` helper is unchanged: the `accuracy` helper on however many items were passed, verdict `sample-sanity`, or `not-measurable` without gold labels. Recorded values on the seeded Banking77 test split (200 messages, 20 per intent, template `This customer message is about {}.`): majority 10.0 / 1.82; frozen zero-shot 82.50 / 81.39; adapted (last two decoder blocks + head, best of two epochs) 97.00 / 96.99; ten unseen messages after adaptation with `sample-sanity` / `measured-small-sample` verdicts. Upstream reports no figure for this use; the MultiNLI accuracy of the base checkpoint is not reproduced here.

###### Decision thresholds

`classify` applies an implicit decision rule and names it in every result (`decision_rule`): with `multi_label=False` the entailment logits are soft-maxed across the labels and the `top_label` is the argmax — no minimum score is required, so a text that fits none of the labels still receives a winner; with `multi_label=True`, or whenever only one label is supplied (the upstream `ZeroShotClassificationPipeline` rule, reproduced here), each label's score is the entailment probability of a softmax over its own `[contradiction, entailment]` logits and no threshold is applied, so the caller sees independent scores and must decide which count as present. No acceptance threshold was set during development. A deployment that needs one must choose it on its own labelled data, trading the cost of a wrong confident label or a spurious extra tag (false positive) against a missed class (false negative) for its application, and must re-set it whenever the label wording or the hypothesis template changes, because both move the score scale. The one selection rule in the adaptation path is explicit: `adapt` keeps the epoch with the highest validation accuracy under the labels and template it was given (epoch 0 is the frozen model, so a run that never improves returns the base weights unchanged) and reports `best_epoch` and the per-epoch history; whether the resulting gain on the test split is worth deploying is the operator's decision and no threshold is shipped for it.

###### Approaches to uncertainty and variability

Every reported corpus metric is one value on one seeded split of one corpus: `build_sample_dataset(seed=42)` fixes the balanced 400 / 100 / 200 draw from Banking77's own train/test files, `adapt(seed=0)` fixes the shuffle order and the choice of wrong phrase per record, and no repetition over seeds or splits is performed, so no confidence interval or standard deviation is available and none is claimed — the +14.50-point accuracy gain on the test split is a point estimate whose spread is unknown, and the ten-message `sample-sanity` verdict says so explicitly. `accuracy` is estimated by a single pass over whatever items the caller supplies, with no resampling and no dispersion; the `evaluation_report` records this (`estimation: single pass over n item(s); no dispersion`), and a caller who needs an interval must bootstrap over their own labelled set. Inference is deterministic given the same weights, device and library versions: dropout is disabled by `model.eval()`, there is no sampling, and no seed is required; small numeric differences between CPU and GPU kernels can reorder near-tied labels. The `score` field is not calibrated: it is a softmax over entailment logits whose scale depends on the label wording and the template — the smoke run gave `travel` 0.9939 against two unrelated labels, and the same premise would score differently against a different label set — so a caller who needs a probability of class membership must fit a calibration map on their own labelled data. The per-label `entailment_logit` and `contradiction_logit` are returned so that the caller can inspect the raw signal behind each score.

#### Ethical considerations and biases

###### Data

The upstream README discloses the fine-tuning data as the MultiNLI dataset and links the base model; the disclosure stops there — no per-genre composition, annotator demographics or licensing of the underlying premises is given in the pinned README, and the BART pre-training corpus (books, news, web text and stories per the BART paper) is described only in the paper. MultiNLI premises come from published and web text and crowd-written hypotheses, so the presence of personal data in the training corpora is not ruled out; whether any of it is sensitive is not known. This repository distributes code, tests and documentation; the 1.63 GB snapshot (`model.safetensors`, `config.json` and tokenizer files) is git-ignored and staged locally under `weights/bart-large-mnli/` with a manifest. The adaptation sample is not shipped either: `fetch_corpus` downloads two pinned objects at run time — `train.csv` and `test.csv` of Banking77 (839,073 / 239,961 bytes; SHA-256 `b06e26ac…` / `d12d6e3b…`) from `raw.githubusercontent.com` at the pinned `PolyAI-LDN/task-specific-datasets` commit `57ec275d…`: 13,083 crowd-written customer-support messages over 77 banking intents under CC BY 4.0 (Casanueva et al., 2020), of which the tutorial keeps ten — refuses any other bytes, and caches them under `weights/banking77/` (git-ignored). The messages are synthetic customer queries written for the benchmark and name no real customers, but they describe cards, transfers and identity checks in the first person; the sample is used only to fit and score the last two decoder blocks and the head, and the balanced 400 / 100 / 200 subset is reproducible from the digests and `SAMPLE_SEED = 42`. An adapter trained on the sample is a derived work of the MIT-licensed weights and inherits the corpus's attribution obligation. Nothing in this corpus is a substitute for the operator's own labels: BYOD records pass through the same validation and are written to `outputs/…_train.csv` in the notebook, so a customer-support log with its intent labels is restricted data the moment it is loaded. The operator must audit the text they submit or train on for personal, confidential or proprietary content and must not log or retain classifications of such text without the same controls they would apply to the text itself; the pipeline performs no such check.

###### Human Life

The pipeline is not intended for decisions in health, safety, criminal justice, employment, credit, housing or any other domain central to human life, and it has not been validated or certified for any of them by anyone. Its only validation is the offline unit suite (35 tests, plus 2 model-backed tests that run when the snapshot is staged) and the CPU runs recorded in this repository on synthetic sentences and banking-support messages. Where a sensitive use is foreseeable — for example triaging patient messages by urgency, flagging job applications by inferred category, or fine-tuning on such material — it is admissible only with a human reviewer on every consequential outcome, an independent domain evaluation on representative labelled text, and whatever regulatory clearance the domain requires.

###### Mitigations

Implemented and inspectable in `src/bart_zero_shot_classification_pipeline/pipeline.py`: (1) supply chain — `MODEL_REVISION` is a 40-hex commit; `stage_missing_files` refuses a manifest naming another model or revision and fetches only manifest-listed files at the pinned revision, and `verify_snapshot` re-hashes every file in `weights/bart-large-mnli/dimer-base-manifest.json` and raises on the first size or SHA-256 mismatch before any weight is loaded; both run before `torch` or `transformers` is imported (`tests/test_import_boundary.py`); the Hub path is taken only with `allow_download=True` and always with `revision=MODEL_REVISION`; `trust_remote_code=False` on both tokenizer and model. (2) Input integrity — `_check_text` rejects non-`str`, empty and over-`MAX_TEXT_CHARS` premises, `_check_labels` rejects non-list, empty, oversized (`MAX_LABELS`, `MAX_LABEL_CHARS`), non-string and duplicate labels, `_check_template` requires exactly one `{}`, `multi_label` must be a `bool`, and `_check_input_tokens` rejects any pair over `MAX_TEXT_TOKENS` instead of truncating. The public `validate_inputs()` helper applies those same checks through the same private functions and returns one input manifest (schema, ceilings, per-input observations, the hypotheses that will be scored, verdict, findings), so a caller can record exactly what was accepted or rejected without duplicating the validation logic. (3) Reproducibility — exact `==` dependency pins, `model.eval()`, float32, and `model_id`/`model_revision`/`device`/`source`/`decision_rule` in every result. (4) Refusals — no generation and no raw NLI on caller-built hypotheses are exposed; a missing snapshot with `allow_download=False` raises `FileNotFoundError`. (5) Dataset integrity — `fetch_corpus` verifies the byte count and SHA-256 of each pinned file before it is parsed; `read_corpus` checks the columns, row counts and intent count; `validate_dataset` enforces the record schema, the id pattern, the size bounds, the character and label ceilings and, when a label set is given, membership in it, and returns a content digest; `check_split_disjoint` fails on any text shared between splits; `build_sample_dataset` draws balanced seeded samples and `split_dataset` is stratified and seeded. (6) Training and artifact integrity — `adapt` trains only whole decoder blocks and the head under an explicit `trainable_decoder_layers` bound, builds its pairs from the validated records with a seeded wrong-label choice, restores the best-epoch weights so a failed run leaves the base model, and truncates training pairs at 256 tokens (the only truncation, training only); `save_artifact` writes a safetensors file of the trained tensors plus a manifest carrying the format tag, the base model id, revision and weight digest, the labels and template it was trained with, the tensor list and the file SHA-256; `load_artifact` refuses any mismatch in the base fields, any tensor outside `model.decoder.layers.*` / `classification_head.*`, and any digest drift, so an adapter cannot be applied to a different base or altered in transit without failing. No statistical mitigation (debiasing, re-weighting, calibration) is applied: the base weights are redistributed unmodified and the adapter learns whatever labels the operator validates.

###### Risks and harms

Confident wrong label: with `multi_label=False` the scores always sum to one, so a text that matches none of the labels still receives a high-scoring winner (mechanically, the least-contradicted hypothesis wins); the operator bears the harm when that label is acted on, and the likelihood is high whenever the label set is incomplete. Label-wording sensitivity: the same text scores differently under `sports` and `athletics`, because the hypothesis sentence changes; a deployment that tunes label names on a few examples can overfit them. Bias reproduction: entailment judgements were learned from crowd-written MNLI hypotheses and web-scale pre-training text, so labels that name social groups, occupations or attributes can rank differently for premises that differ only in a group term; data subjects and third parties bear the harm when such rankings feed a downstream system. Memorised or stereotyped associations surface as spurious entailment. Adaptation drift: an adapter trained towards ten phrases and one template changes the model's zero-shot behaviour on every other label set in ways nothing here measures, and a corpus whose labels encode a biased routing policy teaches that policy; the artifact records the labels and template it was trained with but not the texts, so a misapplied adapter is a supply-chain risk of the operator's own making — the base-digest binding stops it from loading on the wrong model, not on the wrong label set. Automation bias: a reviewer shown a scored label list checks it less carefully. Resource exhaustion: a 32-label call on a long premise runs 32 pairs of up to 1024 tokens through a 407 M-parameter model in one batch, which can exhaust memory on a small host; the ceilings bound but do not eliminate this. Magnitude ranges from a mis-filed ticket to a discriminatory triage of people.

###### Use cases

The pipeline must not be used for surveillance, biometric or demographic profiling, or social scoring — including classifying people's messages by inferred gender, ethnicity, religion, health status or political opinion with labels that name those attributes. It must not support unlawful discrimination in employment, housing, credit, insurance, education or healthcare access, for example by triaging applications or claims into categories that proxy for a protected characteristic. It must not power deceptive or manipulative applications such as targeting persuasion at people classified by vulnerability. Any use that violates the MIT terms of the upstream weights (the licence and copyright notice must accompany redistributed copies) or the DIMER deployment terms is prohibited. The developers identify no further prohibited use beyond these because the model's output is a ranked list of caller-supplied labels.

## Input/output contract

- `BARTZeroShotClassificationPipeline.from_pretrained(device=None, weights_dir=None, allow_download=False)`
- `classify(text, labels, *, multi_label=False, hypothesis_template=HYPOTHESIS_TEMPLATE)` — `text`: `str`, 1–8000 chars; `labels`: list of 1–32 unique non-empty `str` ≤ 100 chars each; every premise+hypothesis pair ≤ 1024 tokens. Returns `{"labels": [{"label", "score", "entailment_logit", "contradiction_logit"}, ...] (sorted by descending score), "top_label", "multi_label", "hypothesis_template", "decision_rule", "n_tokens", "device", "source", "model_id", "model_revision"}`.
- `validate_inputs(texts, labels, *, multi_label=False, hypothesis_template=..., names=None)` — input manifest for a batch of premises sharing one label set; raises exactly as `classify` does.
- `evaluation_report(results, gold_labels=None, *, sample_kind="synthetic")` — `accuracy` of `top_label` against `gold_labels` (`verdict: sample-sanity`) or `verdict: not-measurable` without them.
- `evaluate(records, labels=None, *, multi_label=False, hypothesis_template=HYPOTHESIS_TEMPLATE)` — validated `{id, text, label}` records (1–2,000) classified over `labels` (default: the dataset's own label vocabulary) → `{n, accuracy, macro_f1, n_labels, per_label, predicted_outside_gold_vocabulary, definitions, labels, multi_label, hypothesis_template, verdict, adapted, seconds, model_id, model_revision}`.
- `adapt(train, val, *, labels=None, epochs=2, lr=2e-5, batch_size=16, trainable_decoder_layers=2, seed=0, hypothesis_template=HYPOTHESIS_TEMPLATE, progress=None)` — requires `from_pretrained`; `train` 8–20,000 records, `val` optional (1–2,000; without it the final epoch is kept); one entailment and one contradiction pair per record; fine-tunes the last *k* decoder blocks plus `classification_head` (`k` 1–12; `epochs` 1–20, `batch_size` 1–64, `lr` (0, 1e-3]) with AdamW and keeps the epoch with the highest validation accuracy; returns `{trainable_decoder_layers, n_trainable, n_total, epochs, best_epoch, selection, lr, batch_size, max_train_pair_tokens, labels, hypothesis_template, pairs_per_record, n_train, n_val, seed, history, trainable_names, seconds}`; sets `pipe.adapter`.
- `save_artifact(directory, metadata=None)` → directory with `adapter.safetensors` (trained tensors only) + `manifest.json` (`format` = `org.valcorza.bart-large-mnli.adapter.v1`, base `model_id`/`model_revision`/`weight_sha256`, `tensors`, `sha256`, the training labels and template); `load_artifact(directory)` verifies the manifest — the supported `format_version`, the pinned base id / revision / weight file / digest, exactly one contained `adapter.safetensors` entry whose size and SHA-256 match, and the exact decoder-layer and classification-head tensor set the recorded `trainable_decoder_layers` implies — **before** deserialising, applies the tensors in place and returns the manifest (the digest detects corruption or drift of the weights relative to the adjacent manifest; it is not authenticity against an actor who can replace both files); `adapt` is transactional — if training, validation or the progress callback raises, the pre-adaptation tensors and frozen flags are restored; `BARTZeroShotClassificationPipeline.from_artifact(directory, *, device=None, weights_dir=None)` loads the verified base and applies it.
- `metrics.py`: `classification_metrics(predicted, gold)`, `majority_baseline(records)`. `samples.py`: `fetch_corpus(cache_dir=None, fetcher=None)`, `read_corpus(files)`, `filter_records(records, label_set=LABEL_SET)`, `build_sample_dataset(corpus, seed=42, sizes=SAMPLE_SPLIT)`, `fetch_sample_dataset()`, `validate_dataset(records, labels=None)`, `dataset_digest`, `label_names(records)`, `check_split_disjoint(splits)`, `split_dataset(records, val_fraction=0.15, test_fraction=0.2, seed=0)` (stratified), `load_byod_dataset(path)` (CSV / JSON / JSONL), `write_dataset_csv(records, path)`; constants `LABEL_SET` (ten intents → phrases) and `DEFAULT_HYPOTHESIS_TEMPLATE`.
- `accuracy(predicted, gold)` — exact-match fraction.
- `verify_snapshot(path=None)` — returns the manifest dict with `path`; raises `FileNotFoundError` / `ValueError`.
- `stage_missing_files(path=None, *, allow_download=False, downloader=None)` — returns the relative paths fetched (`[]` if none were missing).
