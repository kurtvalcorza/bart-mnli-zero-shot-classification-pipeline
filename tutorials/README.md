## What changed from the inference-only tutorial

The previous notebook (`TASK-INFERENCE`) classified three synthetic sentences and reported a `sample-sanity` accuracy on the author's expected labels. This notebook keeps that inference contract as Section 5 and adds the adaptation contract around it: a real labelled corpus with readable label phrases, corpus-level accuracy and macro-F1 in the carried `metrics.py`, the majority baseline, a bounded fine-tuning on NLI pairs built from the labelled messages, and an artifact that reloads. The batch `evaluation_report` helper is unchanged; `pipe.evaluate` is the corpus-level stage (`measured` / `measured-small-sample`).

## Conformance notes

- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository import. Section 2 embeds the repository's 3 modules verbatim in topological dependency order (each tagged `metadata.dimer.embedded_module`; the only rewrites make `DEFAULT_WEIGHTS_DIR` working-directory-relative and remove internal relative package imports), Section 3 carries the 7-file snapshot manifest inline and asserts it against the module's constants before fetching, and `NOTEBOOK_SOURCE` records the repository, revision and module digests in the exports.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries a fresh clone lacks (the git-ignored `model.safetensors`), at the pinned revision; `verify_snapshot` re-hashes every entry; `BARTZeroShotClassificationPipeline.from_pretrained(weights_dir=WEIGHTS_DIR)` loads the verified files (`local_files_only=True`, `trust_remote_code=False`); no cell outside the carried modules calls `huggingface_hub`, `transformers`, `safetensors` or `urllib`.
- **Data (DAT1–DAT9, ST6):** the default sample is two pinned objects — `train.csv` / `test.csv` of Banking77 (839,073 / 239,961 bytes; SHA-256 `b06e26ac…` / `d12d6e3b…`) from `raw.githubusercontent.com` at the pinned `PolyAI-LDN/task-specific-datasets` commit — each refused on any mismatch before it is parsed, filtered to the ten `LABEL_SET` intents mapped to readable phrases and de-duplicated on the message, and drawn by a seeded balanced sample into 400 / 100 / 200 records (40 / 10 / 20 per intent) from the release's own train/test partition (`check_split_disjoint` asserts it). The template adds a second *External access* bullet naming the host, the byte counts and the CC BY 4.0 licence.
- **Stages (§4.1):** `fetch_corpus` + `read_corpus` + `build_sample_dataset` / `load_byod_dataset` + `split_dataset` (sample acquisition) → `validate_dataset` + `label_names` + `check_split_disjoint` + refusal probes (validation, with three digests) → `validate_inputs` + `pipe.classify` with sanity checks in both score modes (inference contract) → `majority_baseline` + `pipe.evaluate` on the frozen model (baseline) → `pipe.adapt` (bounded fine-tuning) → `pipe.evaluate` on validation and test with the comparison and per-label F1 (evaluation) → `pipe.classify` on unseen messages + `evaluation_report` + `pipe.evaluate` (inference) → `pipe.save_artifact` → `BARTZeroShotClassificationPipeline.from_artifact` with the parity assertion (export and reload).
- **Score semantics (UNC1–UNC4):** every score is an entailment-derived softmax — over labels in single-label mode, over `[contradiction, entailment]` per label otherwise — not a calibrated probability; accuracy and macro-F1 are exact top-label matches against gold labels (own implementations); no acceptance threshold ships. Ten unseen messages are scored with a `sample-sanity` / `measured-small-sample` verdict that names the missing dispersion.
- **Baseline and evidence (EVAL6/EVAL10/EVAL11):** the majority baseline and the frozen model are scored on the same 200 balanced test messages as the adapted model, the per-label F1 is printed before and after, and every metric is labelled as one seeded split of one corpus with no dispersion estimate; the notebook says that the adapted scorer's zero-shot behaviour on other label sets is changed and unmeasured.
- **Split integrity (SPL1–SPL8):** the split is seeded, balanced and text-disjoint (the release's own train/test partition; BYOD splits are stratified by label); validation selects the epoch and the test split is used for nothing but the final evaluation; the notebook states that messages from one customer or conversation must be split by that grouping.
- **Ceilings (VAL6):** `MAX_TEXT_CHARS` (8,000), `MAX_TEXT_TOKENS` (1,024 per premise+hypothesis pair, rejected not truncated), `MAX_LABELS` (32), `MAX_LABEL_CHARS` (100), the record bounds (8..20,000), the id pattern and the training-only 256-token pair truncation are stated in the Prerequisites and printed before the model runs; four dataset refusals and one settings refusal are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, user records flow through the same validation, seeded stratified split, baseline, fine-tuning, evaluation, inference, export and reload cells. The expected schema and the privacy guidance — a customer-support log with its intent labels is restricted data — are stated in the Prerequisites and in Section 4, and the training split is written to `outputs/bart_zero_shot_classification_train.csv` in that shape.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
